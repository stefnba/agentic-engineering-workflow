# How `codex debug models` relates to the `/model` picker in Codex CLI 0.172.0

## Answer

- **Default `codex debug models` is a superset of `/model`** for the same config, auth and catalog state, at 0.172.0. Both read one catalog through the same models manager, refresh strategy and cache file. `debug models` prints that catalog unfiltered; the picker filters it. See "What `codex debug models` prints" and "How `/model` builds its list".
- **At a given moment the picker can still lack models that `debug models` lists.** The picker runs in a separate app-server process, draws the list the TUI already holds, and refreshes on its own schedule. #54571 on 0.163.0 reports this against `debug models`. #62313 on 0.171.0 reports it against a fresh app-server `model/list`. In #63424 on 0.170.0, the picker came from an older background app-server daemon. See "When each list is fetched, cached or bundled".
- **`codex debug models --bundled` can differ from `/model` in both directions** whenever an online catalog counts as "remote only", which a ChatGPT sign-in with any listed model triggers. It equals the default form only when no fetch and no cache is used. The live check on 0.159.2 shows a two-way difference between `--bundled` and the default form for one account. `/model` was not opened.
- **Neither list is the full set of usable models.** `--model` or `model = …` in config accepts any slug, with fallback metadata for unknown ones. Users report models that work through `--model` but are missing from the default `debug models` output, while `--bundled` lists them. In #47152 `/model` also lacked the model; #51663 concerns the desktop picker.

| List | Catalog source | Filters before printing or showing | Relation to `/model` |
| --- | --- | --- | --- |
| `codex debug models` | Fresh `models_cache.json`, else `/models` fetch, merged with bundled unless remote only | None | Superset, from one catalog state |
| `codex debug models --bundled` | `models.json` compiled into the binary | None | Can differ in both directions when the catalog is remote only |
| `/model` picker | App server `model/list`, same manager and cache | Auth (`supported_in_api`), `visibility == list`, auto models, Reserve-only view | — |

The code evidence is direct and read at one tag. The live evidence comes from 0.159.2 and one account, and `/model` itself was not opened. A maintainer says model availability can depend on the version the CLI reports ([#55658](https://github.com/openai/codex/issues/55658)). No maintainer explains why the server catalog drops models that still work in #47152, #51663 or #55028.

## What `codex debug models` prints

- Both forms run `run_debug_models_command`. `--bundled` prints `bundled_models_response()` and builds no config, auth or manager. The default form prints `raw_model_catalog(RefreshStrategy::OnlineIfUncached, …)` as JSON ([`cli/src/main.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/cli/src/main.rs)) — "let catalog = if cmd.bundled { bundled_models_response()? } else {".
- The bundled catalog is `models-manager/models.json`, compiled in with `include_str!` ([`models-manager/src/lib.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/models-manager/src/lib.rs)).
- At 0.172.0 that file lists gpt-6.2-sol, gpt-6.2-astra, gpt-6-astra, gpt-6.1-sol, gpt-6.1-terra, gpt-6-sol, gpt-6-luna, gpt-5.6-sol, gpt-5.6-terra, gpt-5.6-luna and gpt-5.5 as `visibility: list`. It lists gpt-daybreak-blue-latest, gpt-daybreak-red-latest and codex-auto-review as `hide`. All have `supported_in_api: true` ([`models-manager/models.json`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/models-manager/models.json)).
- `raw_model_catalog` returns every model in the merged snapshot. It does not call `build_available_models`, so it applies neither the auth filter nor the visibility filter ([`models-manager/src/manager.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/models-manager/src/manager.rs)).
- `visibility` takes the values `list`, `hide` and `none` ([`protocol/src/openai_models.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/protocol/src/openai_models.rs)).
- `models.json` entries carry `available_in_plans` and `minimal_client_version`. No non-test `.rs` file under `cli`, `models-manager`, `protocol/src` or `tui/src/chatwidget` reads either name (grep of a sparse clone of rust-v0.172.0, 2026-11-28). The printed `--bundled` output has neither key (tested 2026-11-28 on codex-cli 0.159.2: `jq '.models[0]|has("available_in_plans","minimal_client_version")'` → `false,false`).
- Inferred: any plan gating happens on the server, not in the client, from the two findings above.

## How `/model` builds its list

- The TUI asks the app server for `model/list` with `include_hidden: Some(true)` and `model_provider: None` ([`tui/src/app_server_session/models.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/tui/src/app_server_session/models.rs)).
- The app server answers with `OnlineIfUncached`, then `build_available_models` ([`app-server/src/request_processors/catalog_processor.rs`](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/app-server/src/request_processors/catalog_processor.rs), [`app-server/src/model_catalog.rs`](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/app-server/src/model_catalog.rs), rust-v0.172.0) — "let mut presets = models_manager.build_available_models(models);".
- `build_available_models` applies `ModelPreset::filter_by_auth(presets, uses_codex_backend)` ([`models-manager/src/manager.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/models-manager/src/manager.rs)). That filter keeps a model when the account uses the Codex backend or the model is `supported_in_api` ([`protocol/src/openai_models.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/protocol/src/openai_models.rs)) — ".filter(|model| chatgpt_mode || model.supported_in_api)".
- `uses_codex_backend` is true for `Chatgpt`, `ChatgptAuthTokens`, `Headers`, `AgentIdentity` and `PersonalAccessToken`. It is false for `ApiKey`, `BedrockApiKey`, `BedrockAccessKeys` and no login ([`protocol/src/auth.rs`](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/protocol/src/auth.rs), [`login/src/auth/manager.rs`](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/login/src/auth/manager.rs), rust-v0.172.0).
- `show_in_picker` is derived as `info.visibility == ModelVisibility::List` ([`protocol/src/openai_models.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/protocol/src/openai_models.rs)).
- The popup keeps only `show_in_picker` presets, and its "all models" view also drops auto models ([`tui/src/chatwidget/model_popups.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/tui/src/chatwidget/model_popups.rs)) — "preset.show_in_picker && !Self::is_auto_model(&preset.model)".
- The same file switches to a Reserve-only view while the current model is Luna Reserve and ordinary usage has not recovered ([`tui/src/chatwidget/backend_banners.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/tui/src/chatwidget/backend_banners.rs)), and does not open when `model_picker_unavailable()` returns a message. Under API-key sign-in the TUI filters the reply again with `constrain_api_key_models` ([`tui/src/app/event_dispatch.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/tui/src/app/event_dispatch.rs)).
- `/model <name>` accepts only a model in the TUI's list that is picker-visible; otherwise it says "Model '<name>' is unavailable." ([`tui/src/chatwidget/model_command.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/tui/src/chatwidget/model_command.rs)).
- A configured slug that matches no catalog entry gets synthetic metadata and a warning, not an error ([`models-manager/src/manager.rs`](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/models-manager/src/manager.rs), [`models-manager/src/model_info.rs`](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/models-manager/src/model_info.rs), rust-v0.172.0) — "Unknown model {slug} is used. This will use fallback model metadata."
- Inferred: a model the picker hides can still be set through `--model`, `-c model=…` or `model` in `config.toml`, but not through `/model <name>`, from the two findings above. Whether the backend accepts it was not tested.
- Inferred: from one catalog state, `/model` is a subset of the default `debug models` output, from the `raw_model_catalog`, `build_available_models` and `model_popups.rs` findings. Under ChatGPT sign-in the auth filter passes every model, so only `visibility` and the auto and Reserve cases separate the two.

## Reported mismatches

- **In `debug models`, missing from `/model`.** On CLI 0.163.0, `gpt-6.1-sol` had `visibility: list` in `codex debug models` and worked with `--model`, but `/model` did not list it; open ([openai/codex#54571, 2026-10-16](https://github.com/openai/codex/issues/54571)). On CLI 0.171.0 with ChatGPT login, `/model` lacked both GPT-6.2 models while a fresh `model/list` and a freshly launched picker listed them; open, labelled `auth` ([openai/codex#62313, comment 2026-11-22](https://github.com/openai/codex/issues/62313)).
- **In `--bundled`, missing from the refreshed catalog and `/model`, yet usable.** On CLI 0.155.1, `gpt-5.6-luna` was in `--bundled` only and `codex exec -m gpt-5.6-luna` succeeded; open ([openai/codex#47152, 2026-09-22](https://github.com/openai/codex/issues/47152)). On desktop with Codex 0.162.0-alpha.2, the refreshed catalog dropped the whole GPT-6 family that `--bundled` listed, and a direct request worked; open ([openai/codex#51663, 2026-10-07](https://github.com/openai/codex/issues/51663)).
- **Closed as expected.** On CLI 0.143.0, `/model` omitted GPT-5.6 models that `-m` could start. A maintainer closed it as not planned on 2026-11-15: "starting with that flag doesn't guarantee a picker entry" ([openai/codex#31873](https://github.com/openai/codex/issues/31873)). The maintainer advises updating the CLI and stopping older Codex app-server processes; an earlier maintainer comment (2026-07-18) blamed a stale local app server.
- **Older background app server.** On CLI 0.170.0, `/model` lacked both GPT-6.2 models until the user started with `--no-daemon`. The daemon reported app-server 0.160.0. A maintainer noted that both models list 0.166.0 as their minimum. Updating and restarting the daemon fixed it; closed as completed 2026-11-24 ([openai/codex#63424](https://github.com/openai/codex/issues/63424)).
- **Shared cache.** Two app servers that differ only in `originator` get different catalogs but write the same `$CODEX_HOME/models_cache.json`, which then alternates; open, reported on 0.144.5 and reproduced on 0.162.0-alpha builds ([openai/codex#33593](https://github.com/openai/codex/issues/33593)).
- **Empty output.** With a custom `model_catalog_url` and a download over five seconds, `codex debug models` prints `{"models":[]}` and exits 0; open, reported on 0.164.0 and reproduced on `main` 2026-10-23 ([openai/codex#56528](https://github.com/openai/codex/issues/56528)).
- **No fix in 0.172.0.** Its release notes (2026-11-24) list no picker or catalog fix. Their one model-discovery entry, #62499, adds a Daybreak availability field to `model/list` ([release rust-v0.172.0](https://github.com/openai/codex/releases/tag/rust-v0.172.0)). PR #63553, which caches picker lists per provider and clears them when the account changes, merged 2026-11-24 but is not in the tag (`gh api … compare/rust-v0.172.0...9038698f` → `diverged`) ([openai/codex#63553](https://github.com/openai/codex/pull/63553)). It ships from 0.174.0-alpha.2 on; alpha.1 does not contain it (`compare` → `diverged`).

## When each list is fetched, cached or bundled

- `OnlineIfUncached` means "Use cache if available and fresh, otherwise fetch from the network." ([`models-manager/src/manager.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/models-manager/src/manager.rs)). The default `debug models` form therefore refreshes only on a cache miss.
- The cache is `$CODEX_HOME/models_cache.json` with a TTL of 300 s (`DEFAULT_MODEL_CACHE_TTL`, same file). An entry is used only when it is within the TTL and matches the running binary's `client_version` and the current provider and auth identity (`try_load_cache` in `manager.rs`; [`models-manager/src/cache.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/models-manager/src/cache.rs)).
- `debug models` uses the same cache file as the TUI's app server, through `ModelCatalogSettings::disk(config.codex_home)` ([`core/src/thread_manager/model_catalog.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/src/thread_manager/model_catalog.rs)).
- The manager fetches only for a gateway catalog, Codex backend auth, command auth, or supported API-key discovery (`should_refresh_models`, `manager.rs`). With API-key discovery off, it ignores any cache and returns the bundled list (`SelectedCatalog::Fallback`, same file).
- A new manager starts from the bundled catalog. A failed or timed-out fetch keeps the last snapshot, which on a cold start is that bundled seed (`manager.rs`). The `/models` request times out after 5 s ([`model-provider/src/models_endpoint.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/model-provider/src/models_endpoint.rs)).
- After a fetch or cache load, the bundled models are merged in, with server entries replacing by slug, unless the result is "remote only". It is remote only when any model has `visibility == List` and the auth has a ChatGPT account or API-key discovery is supported (`apply_remote_models`, `manager.rs`).
- A provider with `model_catalog_url` gets no bundled models. A `model_catalog` in config gives a static manager that never fetches or reads the cache ([`model-provider/src/provider.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/model-provider/src/provider.rs)).
- The app server refreshes its catalog with `Online` every 270 s ([`app-server/src/models_refresh_worker.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/app-server/src/models_refresh_worker.rs)). The popup shows the list the TUI holds from bootstrap first, then sends `FetchModels` and updates ([`tui/src/chatwidget/model_popups.rs`, rust-v0.172.0](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/tui/src/chatwidget/model_popups.rs)) — "Show cached choices immediately and update any still-present picker when the reply arrives."
- Live check (tested 2026-11-28 on codex-cli 0.159.2, not 0.172.0, one signed-in account): `codex debug models` printed gpt-6.1-terra, gpt-6.1-sol, gpt-6-sol and gpt-6-luna as `list`, and gpt-reserve and codex-auto-review as `hide`. `codex debug models --bundled` printed gpt-6-astra, gpt-6.1-sol, gpt-6-sol, gpt-6-luna, gpt-5.6-sol, gpt-5.6-terra, gpt-5.6-luna and gpt-5.5 as `list`, and gpt-daybreak-blue-latest, gpt-daybreak-red-latest and codex-auto-review as `hide`. Every entry had `supported_in_api: true`. `/model` was not opened.
- Inferred: `--bundled` equals the default form only when no fetch happens and no cache is used, such as API-key auth with discovery off, no login, or every fetch failing on a cold start. Otherwise, with a remote-only catalog, it differs in both directions, as the live check shows. This rests on the seed, `should_refresh_models`, fallback and `apply_remote_models` findings.
- Inferred: `debug models` and the picker can come from different fetches at one moment. The picker may show its bootstrap list, the app server's 270 s worker may have updated its state, and a cache miss makes each process fetch on its own. This rests on the TTL, refresh-worker and popup findings, and fits #54571 and #62313; no maintainer confirms it for those issues.

## Open questions

- What `constrain_api_key_models` removes under API-key sign-in was not read. If it drops models beyond `supported_in_api`, the API-key case narrows further, but the superset relation holds.
- Whether the CLI and the app server always compute the same cache identity, given `RuntimeAgentInstances` runtime auth and per-originator catalogs, was not checked. Unequal identities would mean they never share a cache entry.
- Why the server catalog drops models that still work through `--model`, and whether that is plan gating, has no maintainer statement in #47152, #51663 or #55028.
- Nothing was run on 0.172.0 itself, and `/model` was not opened in the live check.
- No release newer than 0.172.0 is stable (GitHub latest and npm `latest`, 2026-11-28). Pre-releases 0.174.0-alpha.1 to alpha.9 exist and carry #63553 from alpha.2, so the picker relation may change in 0.174.0.
