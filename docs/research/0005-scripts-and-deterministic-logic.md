# Code and prose in seven agent workflow skill repositories

## Answer

The seven repositories range from no workflow-time code to a CLI that every skill calls. The table compares them at their release tags. Line counts include comments and blank lines, so they are rough.

| Repository | Code at workflow time | Maintainer-only code | Writes workflow state | How code is tested | Hooks over the history |
| --- | --- | --- | --- | --- | --- |
| superpowers v7.0.2 | Skill scripts for the plan ledger, workspace, task briefs, review packages and a brainstorm server (2,261 lines), one SessionStart hook, per-harness adapters; skill prose is 8,475 lines | Release scripts; tests of 11,256 lines | Agent writes specs and plans; scripts write the ledger, briefs and review packages | Local shell, Node and pytest tests, no CI; skill-behaviour evals in a separate repository, run live by hand | One SessionStart hook since 2025-10-09; a Codex hook added 2026-05-14 and removed 2026-06-25/30 |
| mattpocock/skills v1.3.2 | None that skills call; templates the agent copies and one git-guard hook it installs (497 code lines in all); skill prose is 4,148 lines | Changeset and link scripts | Agent, for every file | No tests; a frontmatter-parse CI check on `main` since 2026-11-19 | No active hook ever shipped |
| elephant-goldfish-model v0.1.1 | None; an OpenCode installer the user runs once | Packaging, site and tests (about 6,330 lines in all); skill prose is 2,238 lines | Agent, for every file | pytest in CI, native harness probes in CI; live Claude and Codex tests opt-in | A PreToolUse hook added 2026-10-23, removed 2026-10-27; a test now forbids hooks |
| spec-kit v1.4.5 | `specify` CLI (85,272 lines) and per-step scripts, each in bash, PowerShell and Python (5,515 lines core, 5,160 extensions); command templates, extensions and presets are about 6,400 lines | Tests of 209,791 lines; CI helpers | Scripts create the feature folder and `spec.md`; agent writes the content and `tasks.md` | pytest in CI; extension-hook behaviour tested by hand | Extension "hooks" that the agent carries out from prose since 2026-02/03; native runtime hooks since 2026-07-29, still being fixed |
| OpenSpec v2.2.0 | `openspec` CLI (57,787 lines), called by every skill; skill prose is 3,019 lines | Build and release scripts; tests of 94,328 lines | CLI scaffolds, archives and merges specs; agent writes content and ticks tasks | Vitest in CI; no test runs a model | No hooks; prose "lifecycle actions" served by the CLI merged on `main` 2026-11-28 |
| gsd-core v1.23.0 | CLI from 188,922 lines of source, 45 hook files (16,224 lines), installer, MCP server; workflow, agent, command and skill prose about 32,000 lines | 34 CI workflows; tests of 835,073 lines; mutation testing | CLI writes `STATE.md` fields when prose calls it; agent writes content | Node tests, lint and mutation ratchet in CI | Grew from a statusline (2026-01-16) to guards on seven host events; a context hook unregistered on Codex and seven other hosts |
| BMAD-METHOD v6.12.4 | Python scripts run with `uv run` from prose (5,276 lines); a Node installer the user runs (15,953 lines); skill prose is 12,258 Markdown lines | Validators, docs tooling, tests | Scripts write config, decision logs and the sprint file; agent writes documents and per-story status | unittest and Node tests in CI and pre-commit; `main` adds a model-run eval skill, used by hand | Only a git pre-commit hook; voice hooks under `.claude/hooks/` for two days in 2025-10 |

- **Where code does a workflow step, it takes the step with one right answer.** Paths, numbering, scaffolds, ledgers, status merges, archive moves and config merges go to code; content and judgement stay in prose. BMAD, OpenSpec and GSD state this split in their own words; a superpowers user's request to write it into `writing-skills` is open and its PR closed for want of eval evidence. See [Code, state, tests and hooks in BMAD-METHOD](#code-state-tests-and-hooks-in-bmad-method), [Upkeep reported in OpenSpec, gsd-core and BMAD-METHOD](#upkeep-reported-in-openspec-gsd-core-and-bmad-method) and [Superpowers issues on scripts versus prose, and its evals](#superpowers-issues-on-scripts-versus-prose-and-its-evals).
- **Most reported code breakage sits where the code meets a host it does not control.** The hosts are the shell (PowerShell, cmd, dash, Git Bash, macOS bash 3.2), Windows encodings and paths, each harness's hook format, packagers that strip execute bits, and the runtime on `PATH` (`node`, `uv`, Python). All five repositories that ship workflow-time code report this; the evidence is many dated issues and changelog entries, not a measured share of each tracker.
- **Each extra script language multiplies the upkeep.** spec-kit's three-language scripts drew a run of parity fixes, and its maintainer plans Python only (#4884, open, stale). Its own attempt to move hook ordering from prose into three-language scripts became opt-in and closed unmerged (#4883, #4959, 2026-11-04).
- **Hooks drew per-host fixes wherever they shipped, and several were removed.** EGM removed its only hook after four days. Superpowers dropped its Codex hook because Codex triggers skills itself. gsd-core unregistered a hook that could never fire on Codex and seven other hosts. Many of the hook failures were silent.
- **Moves between prose and code go both ways, and the record is split.** BMAD and GSD moved steps from prose into tested scripts and hooks; superpowers added scripts to keep diffs out of context. OpenSpec's maintainer weighs moving its spec merge from code to the agent after 46 fix commits (#2033, open), and OpenSpec's new lifecycle actions are agent instructions served by its CLI, with no native command execution (#2305), while user requests for executable hooks stay open (#682, #1910).
- **Both prose steps and script calls from prose fail.** Agents skip prose steps (superpowers #2282, OpenSpec #825, BMAD #2397, #2863). Agents also pass wrong script arguments in 11% of measured calls (BMAD #3179), and harness guards or permission prompts stop script calls (superpowers #2469, GSD #5323).
- **No repository runs agent-behaviour tests in CI.** Code is tested in CI wherever it is tested at all. Superpowers, EGM and BMAD `main` run model-in-the-loop evals by hand or opt-in; superpowers grades its evals partly with deterministic shell checks.
- **The evidence dates fast.** Several cited items are days old on 2026-11-28. BMAD `main` is a v7 preview that has diverged from v6.12.4, and OpenSpec's lifecycle actions are on `main` but in no release.

## Code, state, tests and hooks in google/elephant-goldfish-model and github/spec-kit

- EGM's skills contain no executable files. Its code is an OpenCode installer (146 lines), two release scripts, a site and tests, about 6,330 lines in all. Skill Markdown is 16 files with 2,238 lines (tested 2026-11-28: `git ls-files` and `wc -l` at `v0.1.1`).

Native Copilot, Cursor and OpenCode probes also run in CI (tested 2026-11-28: `.github/workflows/` in the clone). The probes run no model: the Copilot probe "uses no model" and the Cursor job "does not authenticate or call a model" (tested 2026-11-28: `copilot_controlled_probe.py` and `cursor-native.yml` at `v0.1.1`).

It removed the hook on 2026-10-27 (tested 2026-11-28: `gh api --method GET repos/google/elephant-goldfish-model/commits/a9738d4` and `.../f91dccb`).
- An EGM test asserts that no hook comes back: "Bundled resources must not carry an automatic permission override" (tested 2026-11-28: `tests/unit/test_harnesses.py` at `v0.1.1`). The privacy doc says the runtime "installs no permission-approval hook" ([docs/privacy.md, v0.1.1](https://github.com/google/elephant-goldfish-model/blob/v0.1.1/docs/privacy.md)).

Hook behaviour is tested by hand: a person opens "a chat with an LLM (like GitHub Copilot)" ([tests/hooks/TESTING.md, v1.4.5](https://github.com/github/spec-kit/blob/v1.4.5/tests/hooks/TESTING.md)).
