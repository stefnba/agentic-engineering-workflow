Run the deletion test and the Guards against over-engineering of the `codebase-design` skill over the scope: list every port, extracted rule object, layer, registry, wrapper, option, and parameter, and ask of each whether removing it would concentrate complexity or only move it. A module that only forwards calls, a wrapper around a library nothing replaces, a rule object with one caller, a registry or runner for cases that differ by behaviour, a layer directory with no navigation or dependency benefit, a parameter or option every caller passes the same way, generality no caller exercises, and code nothing reaches are findings. The trace test runs here too: follow one request end to end and apply the deletion test to every file it crosses. Whether a thing that should exist sits in the right place is the design scanner's question, not yours.
